# 中亚合作项目承诺协调

承接中亚经贸对接（辽洽会）后的主体核验、资源暂留和项目履约。
系统防止同一块土地、同一笔仓容、同一个班列窗口被多个项目重复承诺。

## 领域范围

系统涉及辽宁企业、中亚合作企业、商协会秘书处、地方项目服务人员：

- 合作参与者来自多个中亚国家的机构和企业
- 对接方向包含本地化生产、跨境物流和陆港共建
- 农业种植与精深加工需要联合投资

## 业务规则到实现的对应

| 秘书处要求 | 实现方式 |
| --- | --- |
| 保存四类主体版本及授权联系人 | `parties.py`：主体档案多版本留痕（`profile_at_version`），联系人按权限范围授权 |
| 意向按七口径转成可比较供需 | `intents.py` + `catalog.py`：投资阶段、属地条件、物流资源、农业原料、加工能力、币种口径、保密范围；数量入库即归一到基准单位，汇率版本固定 |
| 候选同时列出满足项、缺口、资源冲突 | `matching.py`：快照含 `satisfied / gaps / conflicts`，并标出占用同一资源的其他组合 |
| 双方确认后才生成有截止时间暂留 | `engagement.py` + `backend.confirm_engagement`：两方确认事件齐备后，组合与四类资源在**同一提交**内占用 |
| 土地、仓容、班列、专家是一个组合原子 | 四类资源行 + 组合聚合多流原子提交，"全有或全无"；`EngagementHeld` 之前任何一类失败则整笔回滚 |
| 尽调按用途授权 | `diligence.py`：授权绑定材料+联系人+用途，访问时用途必须一致并留痕 |
| 译文更正保留原文 | 材料原文为不可变第 0 版，译文与更正只能追加新版本 |
| 联系人离任只终止未完成访问 | `contact_departs` 终止各案卷中 `active` 授权；`completed` 授权与已完成访问记录保留 |
| 改量/延期/终止只释放未履行份额 | 已交接量（fulfilled）与费用是不可变事实；释放量受 `releasable = qty - fulfilled` 约束 |
| 同一业务请求重放不产生第二份承诺 | 命令入口先查幂等流 `idem-{request_id}`，重放直接返回首次结果，不产生任何变更 |
| 跨时区审批依据版本给出单一结果 | `approvals.py`：背书按 UTC 排序；审批案保存 `basis_versions`，执行时版本已变则唯一结论 `stale` |
| 人工调整由未参与发起的人复核 | `manual_adjustment` 审批案拒绝发起人本人背书，须另一人复核 |
| 恢复后继续处理到期与提醒 | `backend.recover()`：暂留到期释放、尽调授权到期终止、履约提醒补发；全部由当前状态守卫，重跑幂等 |
| 项目接口说明责任人/缺口/历次承诺/最终原因 | `projects.build_project_view`：从事件实时重建单一视图 |

## 架构

纯标准库 Python（≥3.11）实现，事件溯源：

```
命令 → 聚合校验不变量 → 多流原子提交（EventStore）→ JSONL 持久化
                                      ↓
查询 ← 聚合重放 / project_view 读模型
```

- `events.py`：事件存储。一条提交记录包含多个流的事件（多流原子性），
  每流带期望版本号（乐观并发，资源争用的串行点），JSONL 追加写 + fsync，
  崩溃留下的不完整尾行在重放时忽略。
- `repository.py`：聚合基类与仓储，聚合状态只能由事件回放得到。
- `clock.py`：内部一律 UTC 绝对时间；IANA 时区仅随操作记录，
  跨时区先后由 UTC 时刻裁决。
- `catalog.py`：单位族换算（亩/公顷/平方米、吨/千克、TEU、人月/人日等）、
  版本化汇率表、维度枚举、保密级别（L1<L2<L3）。
- `parties.py`：主体版本与授权联系人。
- `intents.py`：意向版本与供需条目规范化。
- `resources.py`：土地/仓容/班列窗口/专家支持库存与占用。
- `engagement.py`：组合原子（候选→暂留→承诺→落地/终止/到期）。
- `matching.py`：候选匹配快照。
- `diligence.py`：尽调材料、用途授权、译文版本。
- `approvals.py`：跨时区审批与人工调整四眼复核。
- `projects.py`：项目聚合与项目接口视图。
- `backend.py`：门面，统一鉴权、请求幂等、跨聚合同一提交、审批执行、恢复处理。

### 组合原子状态机

```
proposed ──双方确认──▶ held ──转承诺──▶ converted ──验收──▶ landed
   │                    │                   │
   │（资源冲突不能暂留）  └──── 到期 ──▶ expired
   └──────────── 终止（held/converted）──▶ terminated
```

终止与到期只释放未履行份额；已交接量、交接记录、费用在任何终态后继续留存。

`contracts/domain.schema.json` 定义领域资料结构，`fixtures/domain.json` 提供不含真实身份信息的示例，`src/central_asia_project_commitment/context.py` 负责读取并检查这些资料。

## 开发命令

- 运行测试：`python3 -m unittest discover -s tests -v`
- 编译检查：`python3 -m compileall -q src tests`

上述命令只读取仓库内资料，不需要连接外部业务服务。事件存储默认在内存中，
传入文件路径即落 JSONL，可在进程重启后完整重放。

## 典型流程（经测试覆盖）

1. 登记四类主体并引导首位管理员，授权在职联系人；
2. 登记土地/仓容/班列/专家库存，登记辽宁侧需求意向与中亚侧供给意向（可多版本修订）；
3. `propose_match` 得到满足项/缺口/冲突快照并存为候选；
4. 双方跨时区确认 → 四类资源原子暂留（带截止时间）；
5. 尽调案卷：登记材料、按用途授权、按用途访问、译文与更正追加留痕；
6. 暂留转承诺，记录交接与费用；改量/延期经四眼审批执行；
7. 终止或到期只释放未履行份额；验收合格记录落地原因；
8. 任意时刻 `project_view` 给出责任人、资源缺口/冲突、历次承诺与最终原因；
9. 进程重启后 `recover()` 继续处理暂留到期、尽调待办与履约提醒，且不重复生效。
